## Context

`src/data/ao-data.json` is produced by `pnpm sync:ao && pnpm build:fixture` from
upstream Albion CDN dumps. It was listed in `.gitignore` under the assumption
that it would be "committed only after full pipeline" runs, implying some
external process (CI or deploy) would generate and ship it. In practice, no
such step exists: there is no CI job or deploy step that runs `sync:ao` and
publishes the resulting artifact. Runtime code (`src/app/api/items/route.ts`,
`src/lib/build-card-lookups.ts`) reads this file via `fs` in dynamic server
components at request time. Without the file present in the deployed
filesystem, the app has no item/spell data in production.

During ACM-091, the artifact was regenerated and force-added
(`git add -f`) to unblock the fix, since the app had never worked without it
committed — but the `.gitignore` entry was left stale and no decision was
recorded, which a review correctly flagged as process debt.

## Decision

Track `src/data/ao-data.json` in git as a committed, regenerable artifact.
Remove the `.gitignore` entry (leaving an explanatory comment in its place so
future authors don't reflexively re-add it). The artifact is regenerated
locally by `pnpm sync:ao [--force] && pnpm build:fixture` whenever the data
pipeline changes or upstream content drifts, and the resulting diff is
reviewed and committed like any other source change.

The test fixture `src/__tests__/fixtures/ao-corpus.json` remains separately
committed (pruned corpus for deterministic acceptance tests) and is
regenerated by the same `build:fixture` step.

## Consequences

- The repository carries a multi-MB generated JSON file in history; diffs on
  regeneration can be large and should be reviewed for unexpected drift
  (see `src/__tests__/acceptance.test.ts` lines 100-119, which require
  investigating unexplained pinned-number drift before bumping it).
- If a CI/deploy pipeline that regenerates this artifact is introduced later,
  this decision should be revisited — committing it would then become
  redundant and could be reverted in favor of a build-time generation step.
- `.cache/` (raw CDN dumps) stays gitignored; only the final normalized
  artifact is tracked.
